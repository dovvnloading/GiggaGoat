# Lane integration findings

This file records boundaries encountered in the first-playable integration. No lane-owned source was edited.

1. **Breakable static world props.** Some world descriptors (fences, signs, lamps, benches) are flagged breakable:true but have body.type=static. The chaos BreakableRegistry.register() requires dynamic rigid bodies with colliders. Core replaces those colliders with similarly sized/yawed dynamic Rapier bodies before registering the breakables, rather than silently leaving the flags nonfunctional. Future world data can encode their intended body type and mass directly.
2. **No exported instance map for world props.** WorldScene exposes the root group and chunk/water controls but no ID-to-visual lookup or dynamic-prop update hook. The currently exported scene contains InstancedMesh batches named props-<kind> with insertion order equal to island.props; the core renderer uses that arrangement to animate/hide destroyed instances. If the concurrent visual pass changes grouping/naming, the world lane should eventually export a stable ID-to-transform/visibility API. Game works with its present exported group without modifying world source.
3. **Approximate river buoyancy volumes.** World data exports centerline points and widths/levels, not polygonal water-collider geometry. Core installs axis-aligned segment boxes following the centerline plus a reservoir box; these provide current/buoyancy and avoid requiring new APIs, but wide bends can cover adjacent bank. Exporting water-volume geometry would improve shoreline accuracy.
4. **Different rule and physical ragdoll recovery clocks.** Gameplay balance and physics balance controller have independent recovery thresholds; core forwards impacts to the gameplay ability state and sends flop commands to the real ragdoll, with physical balance authoritative for whether the body is flopped. Both systems remain functional without changing lane behavior.

5. **Street-contact facts for rooftop gigs.** World publishes painted road segments and terrain colliders but no public per-road physical surface identifier. Core reports real height/grounding, not a fabricated `onStreet` contact: Rooftop Express's additional street-height failure check still works, but tracing specific pavement contact will need an exported street collider/road query from world.
6. **Hay Heist bales are rules-owned.** `PartyMatch` exposes bale positions, carrying and scores but no API to bind existing Rapier rigid bodies as bale authorities. Core renders those authoritative bale transforms while the goats themselves remain fully physical ragdolls. A future public hook can support freely simulated bale collisions without duplicating or mutating mode rules.
7. **World prop instancing is currently keyed by kind and insertion order.** As in finding #2, the core tracks the world scene's `props-<kind>` meshes. This remains a compatibility bridge for physical props; a stable exported prop-instance ID mapping would remove the dependency on grouping while the other team changes visuals.

8. **Tide changes must run outside physics hooks.** `WaterSystem.setSeaLevel` wakes every tracked Rapier rigid body. Calling it from `PhysicsWorld.onAfterStep` can re-enter the WASM body set and trap during crowded Rising Tide simulations. Core advances `PartyMatch` once per physics tick, then applies the resulting water height immediately *after* `PhysicsWorld.step` returns, which means catch-up frames can apply a tide jump a few substeps later without compromising the fixed-tick match schedule. World rendering gets the same resulting height each frame.
