# Living Downtown — implementation and review evidence

Implementation PR: [#330](https://github.com/dovvnloading/GiggaGoat/pull/330). Before-state: [`92001c7`](https://github.com/dovvnloading/GiggaGoat/tree/92001c7ec3f851be8468590b237833e0d0e007f8). Production seed: `billy-isle`.

This PR turns the first living-world slice into running game code. The roadmap's acceptance boxes remain open: code, automated checks, art approval and reference-device performance are different evidence. This document records what exists and what still needs review.

### Runtime and resource budgets

- Logical population is independent of graphics quality. Near residents retain full animation; distant animation updates are limited to 12/8/5 Hz on High/Medium/Low and use deterministic travel phase. Far rendering fades without resetting the routine. Residents entering the follow camera's immediate body envelope are temporarily hidden in both renderers; height-scaled entry/exit clearances prevent flicker, near and far visibility are tracked independently, and hidden actors continue their current gait and reactions.
- Five character templates are shared across the cast. Skeletons are cloned per resident; textures, geometry and materials are shared and reference-counted. Fruit is two instanced batches. Windows add no per-window lights, and residents add no per-actor sunlight shadows.
- The navigation search allowance is one route per simulation tick. Actor separation uses a spatial grid. All new routines use the existing physics clock and pause with it.
- The market contributes at most six bodies to the existing dynamic-body budget; it has no recurring spawn queue. It releases owned bodies and budget entries on disposal.
- Gigs, pending gig results, party matches and build mode suppress ambient activity. Mode entry suspends fruit physics before the next Rapier tick. Existing progression, discoveries, rewards and save schemas are preserved.
- Asset failures leave the failed resident/fruit absent instead of displaying placeholder geometry. Late asynchronous completions are disposed safely after teardown.

## Assets and licensing

The pilot reuses the repository's Kenney `mini-characters` and `food-kit` assets. Both are listed as CC0 in the existing [asset library inventory](../../../public/assets/library/README.md). Character files were inspected for the actual skeleton and animation content: the five selected files contain two skinned meshes and 32 native clips each. The renderer selects native locomotion, idle, interaction and emote clips; it does not infer animation coverage from a filename. Fountain, table and window placement follows measured model bounds and existing authored geometry.

## Reproduce browser evidence

The PR's `living-world-evidence` CI job runs the actual `Game`, `GameView`, renderer and audio bridge on the before-state and current change. Its matching WebGL stills use identical seed, High quality, 1280×720 viewport, camera bookmarks and 12 timed samples per view. The separate `living-world-walkthrough` job explicitly selects the game's production software-rendering fallback, with its ordinary 30 Hz frame limit and Low preset in a 640×360 CSS viewport. It validates fallback traversal and sound; a WebGL walkthrough on physical reference hardware remains open. Backend, actual canvas resolution and quality are recorded explicitly. The two jobs upload correspondingly named artifacts and retain independent pass/fail results, so a failed recording cannot pass merely because stills succeeded. The command below requests 24 samples for a longer local measurement. These small headless samples are diagnostic, not statistically reliable reference-device tail-latency acceptance.

With a working Chrome installation:

```bash
npm install
npm run capture:living-world -- --out .living-world-captures/after --label after --samples 24 --tour 100
```

Set `CHROME_PATH` if Chrome is not installed in a standard Linux location. The capture script uses existing dependencies only. `--root` selects a separate checkout; `--seed`, `--quality`, `--points` and `--samples` make the run reproducible. `--tour` adds a continuous 90–120 second scripted controller walk using the real goat camera and the existing audio mix; `--tour-only` omits the still capture. The video defaults to the still quality and 1280×720; `--tour-quality`, `--tour-width` and `--tour-height` independently control it. CI passes `--require-tour-route`, which fails the walkthrough job if the recorded goat does not reach every waypoint, while retaining the video and profile for diagnosis.

The artifacts contain matching JPEGs from spawn, Downtown street/fountain/market/rooftop and eight district approaches, a raw `profile.json` for each checkout, and an uncut `gameplay.webm` for the implemented game. The profile records exact checked-out SHA and dirty state, seed, quality, camera, resolution/DPR, browser, renderer, OS/CPU, individual timing samples, p50/p95/p99, draw calls, triangles, texture/geometry counts, physical bodies, actor states and browser errors. GitHub PR jobs normally check out the synthetic merge commit; use the associated run's head SHA to identify the branch revision. The tour additionally records simulation and render-submission work, actual elapsed simulation, dropped time, reached waypoints, reactions and codec. Fixed views hide the HUD to expose the scene. The tour restores the page HUD, but the video records the game canvas and audio without compositing DOM overlays. The clip uses automated controller input; it is not a human acceptance tour. Pass `--software-renderer` to reproduce the explicit fallback selection; without it, the production renderer chooses WebGL when available.

### Baseline asset issue discovered during capture

The first two capture attempts correctly failed their authored-goat readiness check. Diagnostics identified an existing Vite transformation of `new URL('/', import.meta.url)` into `/@fs/`, causing the goat GLB request to receive the HTML application fallback instead of the model. The old game then displayed its legacy goat sculpt. This PR fixes the public asset URL and regression-tests the actual Vite transformation and resolved development/production URLs. Direct HTTP verification confirmed that the corrected path returns the GLB header and the incorrect path returns HTML.

The recorded baseline source stays unchanged. Its capture alone uses the explicit `--allow-legacy-goat` flag and records the legacy state in the profile, preserving the actual before-state. The implemented game must load the authored goat and the entire resident cast. No corrected source or redirected asset is silently substituted into the baseline. Failed-run diagnostics remain available in [the first capture run](https://github.com/dovvnloading/GiggaGoat/actions/runs/45643701717) and [the diagnostic run](https://github.com/dovvnloading/GiggaGoat/actions/runs/45646262384).

**Measurement correction and limits:** still profiles measure CPU `GameView` submission followed by `gl.finish()`. [Chromium deliberately implements that call as a flush](https://chromium.googlesource.com/chromium/src/third_party/+/master/blink/renderer/modules/webgl/webgl_rendering_context_base.cc), so these values exclude completed GPU rendering, presentation and image readback. Earlier wording calling them completed frames was incorrect. Screenshot wait and tour copy timings expose additional queued work. No reported submission percentile establishes presented-frame FPS or the proposed 16.67 ms reference-device budget. The clip records real wall-clock frame intervals separately. Before-state has no new ambient systems; the same capture harness is applied to both. The fixed camera samples are explicit cuts; only the gameplay clip is continuous.

The first completed artifact, from [the `3886c54` run](https://github.com/dovvnloading/GiggaGoat/actions/runs/45648658197), loaded the authored goat and all 16 residents with no browser errors, but its High-quality recording advanced only 4.10 simulation seconds in 102.99 wall-clock seconds and reached zero waypoints. That clip is diagnostic evidence, not an accepted walkthrough. This finding led to separate video quality controls, per-phase timings and the explicit route-completion requirement. The production timestep and catch-up cap are unchanged.

Later captures isolated additional recording overhead. The [WebGL-only SwiftShader run](https://github.com/dovvnloading/GiggaGoat/actions/runs/45656370686/artifacts/15043648282) reduced total synchronous view work to 1.53 seconds during a 101.08-second recording, yet direct canvas capture still delayed callbacks and completed only one waypoint. The recording harness measures short timer/render/direct-capture/copy-capture probes, requests video frames explicitly, and copies the chosen production renderer's pixels to a CPU-backed 2D recording canvas. This copy is a capture adapter. The profile records copy time, requested frames, callback gaps, component timings and the actual route result; successful traversal and usable decoded media are verified separately.

The [copy-adapter probes](https://github.com/dovvnloading/GiggaGoat/actions/runs/45660242252/artifacts/15045425795) showed the delay even without a recorder: software-emulated WebGL needed roughly half a second to produce/read back a frame in this runner. The 100.58-second clip advanced 18.67 simulation seconds and reached two waypoints; it remains failed diagnostic evidence. The CI walkthrough therefore exercises the existing production software fallback explicitly, with the same real-time physics limits and route-completion requirement. This does not repair, replace or certify hardware WebGL performance. High WebGL comparisons and the existing Chrome regression budgets remain separate.

The [first successful fallback walkthrough](https://github.com/dovvnloading/GiggaGoat/actions/runs/45661704387/artifacts/15045157624), from branch revision `b6726df` / PR merge checkout `7538046bd599cb99ec16e1b011cc08bc13f33d5e`, reached all 11 waypoints in 59.94 wall-clock seconds. The complete clip records 100.36 wall-clock seconds, 99.87 simulation seconds, three resident reactions, all 16 loaded resident rigs and no browser errors or warnings. Independent decoding verified 1,269 VP8 frames at 512×288 and non-silent stereo Opus audio. The street/market route and return are visible. Brief resident intersections with the follow camera around 27–33 seconds remain visible in this historical clip and motivated the subsequent camera-proximity presentation fix; this footage is not presented as a spotless art-acceptance tour.

## Physical reference-device acceptance capture (local)

The headless jobs do not exercise a physical display/GPU or an independent human player. The new local QA page boots the ordinary game (including menus, real player controls, audio, dynamic resolution and the unmodified renderer and physics loop), not the scripted tour controller. It is outside the production build and uses no extra dependencies.

From a clean checkout of the exact PR head on the intended reference device:

```bash
npm install
npm run qa:living-world
```

Open the printed loopback URL in a normal hardware-accelerated Chrome window. Use a fresh browser profile or the isolated local origin, not an existing save. Record device model, OS, GPU/driver, browser version, display refresh rate, AC/battery state, viewport/DPR, quality and ambient conditions. Confirm actual hardware acceleration in chrome://gpu; a renderer string alone is not proof. Do not use headless, SwiftShader, the production software fallback or an unverified renderer as physical-GPU evidence.

1. Select a quality in the ordinary settings and enter Free Roam. Let assets stream fully. Walk to Downtown. Press **N** to begin a profile; press **N** again to download the raw JSON. The page never sends simulated movement or teleports the goat. Press **M** after a rooftop idle and again after revisiting the market to timestamp reviewer observations; these markers are not automatic checks. Include an accepted bleat near residents and an actual crate disruption. Review the resident reaction counts, market-spill event, position history, asset readiness and console errors in the JSON.
2. Capture the independent 90–120 second human tour separately with a screen recorder that includes game audio and HUD. Check animation contact, camera clearance, reaction and recovery, weather readability and scene composition against the reference art. Retain the uncut footage and failed attempts. Do not use a recorded run to establish uninstrumented performance.
3. For each Low, Medium and High preset, run a separate **unrecorded** profile of the same route and a long session (at least 10 minutes; include chaos, culling/revisit, pause/resume, mode changes and a fresh reload). Capture the browser's presentation/compositor frame trace using Chrome Performance or an equivalent physical-device tool; collect GPU/process memory and loading/repeated-regeneration observations separately. Compare the exact same route, resolution, device and quality against the before-state. Keep performance traces and video as distinct evidence. A resize or quality change segments timing samples; paused/hidden intervals are marked, not folded into active gameplay. The 250,000-frame safety limit is explicit in the exported finish reason; start another run rather than treating a capped run as a full session.
4. The raw profile includes clean checkout identity at startup and export, actual canvas size and quality, frame-start interval p50/p95/p99/worst and >33 ms counts, CPU render submission, physics work and dropped time, optional sparse asynchronous GPU timer queries, draw calls/triangles, body/resident/voice counts, resource counts, optional JS heap, browser errors and timed manual markers. Frame-start intervals are **not proof of delivered/displayed frames**; GPU query timings measure GPU render work, not presentation. A software, unknown or dirty/mismatched checkout is not acceptable hardware evidence. Missing/disjoint GPU samples are not zero latency. Never equate texture/geometry counts or JS heap with total memory. Validate actual presentation timing and long-session memory against Q07 separately.
5. Attach raw JSON, before/after traces, human video/audio, screenshots and the independent reviewer's explicit Q01/Q02/Q03/Q04/Q05/Q06/Q07/Q08/Q09 findings to the PR. State PASS/FAIL/NOT EVIDENCED with the SHA, evidence links and remediation. Any missing or failing applicable gate keeps acceptance open. No automatic PASS is emitted by this harness; the roadmap's existing stop rule and proposed budgets are unchanged.

`npm run test:living-world-qa` syntax-checks the local scripts and tests nearest-rank statistics, software-renderer rejection/classification and pause/quality/resolution interval boundaries. The physical-device run and human visual approval cannot be produced by CI.

### Follow-up code review corrections

The source review of [`f4abd8d`](https://github.com/dovvnloading/GiggaGoat/pull/330#pullrequestreview-6063507012) found direct fruit knockback scoring and fallback to ordinary destinations during a failed resident retreat. The corrective changes keep real fruit impulses and audio events but exclude fruit-specific knockback and tongue-swing rewards, release fruit tethers before suppressed-mode solves, and ignore disabled bodies in explosion impulses. Residents clear stale routes on alarm, wait if no safe away route exists, avoid retreat segments that approach the incident, and replan on recovery. Added regression coverage exercises real player bleat input, ordinary-prop scoring as a positive control, disabled-body explosions, real fruit tongue attachment/release, mode-entry tether removal and a blocked retreat. Results from the earlier revision above are historical, not verification of the corrective commit; the new revision must pass the full CI/evidence jobs independently.

### Walkthrough intermittency: root-cause investigation

At corrective head `c54e2c0`, [attempt 1](https://github.com/dovvnloading/GiggaGoat/actions/runs/45683819136/artifacts/15055876319) reached 4/11 waypoints, despite advancing 100.02 simulation seconds with **zero** dropped physics time and no browser errors. The video shows the goat stopping on the final east sidewalk approaching waypoint 5, rather than a frozen renderer. Its final world position was (151.26, 6.50, 160.69). [The successful retry](https://github.com/dovvnloading/GiggaGoat/actions/runs/45683819136/artifacts/15056663656) used the identical merge checkout, seed, route and fallback backend, reached 11/11 by 50.55 simulation seconds, and advanced 99.80 simulation seconds with 0.215 seconds dropped. All 1,375 unit and 25 Chrome tests passed. [The earlier successful recording](https://github.com/dovvnloading/GiggaGoat/actions/runs/45664175873/artifacts/15044744612) also reached 11/11.

The prior fixture sampled movement and waypoint advancement on variable wall-clock render callbacks, computed the next heading from the previous waypoint for one frame, allowed probe timing to change the simulation's starting state, and had no bounded recovery when the goat failed to make progress. The old artifacts do not identify the exact blocking collider; do not infer a specific world-geometry defect from footage alone. The new capture-only controller uses the existing 60 Hz fixed step and unchanged five-step catch-up/drop policy, a deterministic pre-roll, simulation-time reaction pauses, same-tick steering, and bounded ordinary-player sidesteps/re-approaches. All 11 original waypoint coordinates, the 1.2 m arrival radius, movement speed, 100-second recording, and route failure gate remain unchanged. The goat cannot skip waypoints, teleport through blockers or remove scenery. The profile records timestamped positions, velocities, support and forward-query hits, named collision contacts, recovery attempts and an explicit exhausted-route reason. The new regressions cover render cadence, blocked-waypoint non-acceptance, the full original route through Game/Rapier, and a real fixed obstruction at the market approach. Full CI on this corrective revision is required; no hardware or human acceptance is claimed from the earlier retry.

No task is marked accepted merely because its implementation appears in this PR. Q01/Q09 independent approval and Q07 reference-device performance remain open until their evidence is recorded.
